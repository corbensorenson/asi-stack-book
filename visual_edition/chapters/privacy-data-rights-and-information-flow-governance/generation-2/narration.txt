A benefits assistant may read a resident's application to answer one question. Does that access also permit the system to store the application in memory or use it for training?

No. Access answers whether the system can reach the data. Purpose answers why this use is allowed.

Keep one information-use record on screen. The purpose is to explain the current application. The affected person is named. The record expires when the support session ends.

Now map the data flow. The application enters context. A summary is proposed for memory. A feedback collector proposes sending the conversation to a training store.

Only the first flow is necessary for the declared purpose. The other paths need separate justification.

Try a less-data alternative. Instead of mounting the full application, reveal only the fields needed to answer the question. The assistant still succeeds.

Minimization has now changed the actual flow, not merely added a privacy label.

Suppose the person later requests deletion. Removing the source row is only the beginning.

The record traces known copies into cache and backup. It also tracks derived summaries. Some influence may already exist inside a trained model.

Those states need different language. Deleting storage is not the same as removing behavior. A changed answer is not proof that all influence is gone.

Rights must be executable. The person needs notice and a way to challenge the inventory. Each custodian needs a deadline and a response path.

Unknown copies remain visible. A system should not close the request by assuming that every downstream derivative was found.

Now imagine a differential-privacy mechanism protects one training release. That can bound a particular leakage risk under its assumptions. It does not make the original collection compatible with its purpose.

Legal compliance is separate again. A technically complete flow map cannot decide which law applies or whether consent was valid.

Material changes reopen admission. A new recipient or longer retention period changes the use even when the source data is identical.

Finite lifecycle models can preserve these distinctions and reject missing purpose or propagation fields. They cannot prove complete forgetting or lawful deployment.

For the benefits application, the assistant may use the minimum data needed for this support session. Memory and training remain behind their own decisions. Privacy becomes a governed lifecycle, not a promise attached after access was granted.
