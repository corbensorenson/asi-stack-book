A model finds twelve duplicate files and writes the right delete command. Should the command run?

The model's intelligence cannot answer that question. It can propose an action, but it does not own the drive. Correctness and permission are different facts.

Keep the request on screen. It names the files to clean and the person who asked. The model turns that request into a proposal. Nothing has changed yet.

Now place the proposal inside a system. A context boundary reveals only the permitted files. A verifier checks whether the command matches the request. An authority gate asks whether this user may delete these files at this time.

Each layer answers a different question. The model proposes what might work. The verifier checks the stated test. The gate decides whether the effect may happen.

Suppose the command is perfect. The verifier turns green. May it run now?

Not yet. A correct proposal still needs a live grant for this exact effect. When that grant arrives, the execution adapter checks it again. Only then does the delete token cross the boundary.

The tool reports that twelve files changed. That report is useful, but it is not reality itself. A separate observer inspects the drive.

Imagine the observer finds thirteen changes. An opaque agent might keep the green receipt and discard the contradiction. The stack keeps both. The extra deletion becomes a visible residual with an owner.

Because the pre-state was recorded, the system can restore a reversible change. If an effect cannot be reversed, the system needs a compensation or containment plan before acting.

This is why an advanced AI should be treated as a stack rather than one model with every power. A plan does not become permission. A tool receipt does not become observation. A proposed improvement does not become approval of itself.

The architecture has costs. Extra boundaries can add delay and create new failure points. They earn their place only when they improve useful work after verification, recovery, and governance costs are counted.

The file-deletion case shows how responsibilities can be separated and inspected. It does not prove that this particular stack is safe, efficient, or sufficient for general intelligence.

In the file-deletion case, the model supplied a capable proposal. The surrounding system decided what it could see, what had been established, what could act, and how a mistake would remain recoverable.
