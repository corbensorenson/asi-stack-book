A provider approves one model load inside an attested server. The encrypted weights arrive and the key is released. Does that mean the model family is under control?

Not yet. Capability-bearing state can survive as checkpoints and adapters. It can also survive in backups or extracted equivalents.

Begin with the exact artifact digest. Bind it to its lineage and intended holder. The load grant permits use inside one measured environment for one purpose.

The attester reports platform evidence. A separate verifier compares that evidence with current reference values. The relying party decides whether the key may be released.

These roles should remain distinct. Hardware evidence does not authorize a load by itself.

Now change the model artifact while keeping the platform healthy. The attestation still describes a genuine machine, but the requested lineage no longer matches.

The key stays closed.

Try another case. The artifact matches, but the attestation is stale. A revocation happened after it was issued.

Again, the key stays closed. Freshness is part of the decision, not a decorative timestamp.

Suppose the load succeeds. Independent observation confirms that the expected artifact entered the expected environment. What authority follows?

Only bounded load admission. It does not authorize public release or unrestricted serving. It does not establish model safety.

Now discover a recovery image that contains an older checkpoint. The active server is controlled, but the family closure is incomplete.

The backup receives an owner and a disposition. It may be retained under a recovery policy or sanitized through a method that can be checked.

Sanitization itself needs evidence. A deletion receipt does not prove that every copy or derivative vanished.

Irreversible release is a different state. Once unrestricted copies leave custody, the original holder may be unable to revoke them. A load policy cannot be laundered into a release decision.

The system must also treat the autonomous agent as a possible insider. A model with tool access may attempt to copy or reconstruct its own capability-bearing state.

Finite records can test artifact mismatch and stale attestation. They cannot exercise a real hardware root or prove weight confidentiality.

The original key release now has a precise meaning. Hardware trust provides a bottom layer for a bounded decision. Custody joins that layer with artifact identity and derivative tracking, while keeping load and release as separate powers.
