# Live transport placement comparison

This owner-operated follow-up measures caller-to-decision time through a real loopback HTTP gateway using live exact-version delivery reads. The first package pilot used summed fetch timings and a modeled gateway envelope. This follow-up preserves its results and selects eight different package lineages from the same pinned npm CLI lockfile, excluding all twelve earlier names. Selection uses the first eight eligible unique top-level unscoped package names ordered by SHA-256 of `asi-dist-transport-v1:{name}`. Use the eligibility rule from the original protocol. A lockfile-integrity-verified npm tarball supplies the expected SHA-256 of `package.json`. [Original protocol](protocol.md) · [Frozen transport cohort](transport-cohort.json)

Compare conventional caller-side fallback with gateway fallback. Both use the same evidence decision and integrity predicate, exact-version remote paths, and one optional fallback read. Use jsDelivr first and UNPKG second. Both services share the npm publication upstream. The gateway listens only on loopback and accepts fixed cohort keys and known condition identifiers. Each arm performs its own reads. Alternate arm order by package and condition to balance first-read effects.

Test two main conditions on each package. The live condition leaves service responses available. The primary-withheld condition prospectively disables the primary read at the local observation boundary before launching either arm. Test two additional controls on every package. The both-withheld control withholds both reads. The wrong-body control withholds the primary and presents the already fetched, successful second-path body of the next package in cohort order. These three controls describe injected local availability or evidence substitutions. Record any naturally occurring errors separately. An unavailable tarball reference remains in the denominator and forces an unresolved outcome.

Start the monotonic caller clock before the first dispatch. Stop when the caller has read and checked the result. Record outer and upstream HTTP request counts, upstream response body and header bytes, gateway response body and header bytes, and elapsed caller time. Counts apply at each hop, so bytes on two hops are counted twice when sent twice. Record the onboarding/reference and adverse-control fetches separately. Do not interpret the difference as a production effect on CPU, billing, full wire volume including TLS, or active human time. Record verification, unresolved, and unsupported verification on each arm. No package code executes.

The pilot supports further placement work only if both arms verify the same exact outcomes in both main conditions, at least three lineages reach a verified fallback in each arm under primary withholding, and both controls produce zero false closures. Use a provisional placement threshold of 1,000 ms maximum added paired median caller time and 8 KiB maximum added response bytes per verified fallback in the gateway arm. This small screening comparison cannot establish an outage-rate or production-adoption bound. A timed human evidence comparison requires consenting participants under the existing draft-only outreach boundary.
