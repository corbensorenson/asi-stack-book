# Receiver evidence in public package distribution

Freeze this protocol and the cohort before opening the selected package responses. This owner-operated pilot uses real remote receivers and published package-version lineages. It revisits the availability question from the local receiver runs. It compares read paths after publication and does not send a release, repeat a write, or test already ambiguous writes. The client runs from one location.

The target is receipt of the exact `package.json` file of a package version at the observation time. The npm CLI lockfile at commit `977fd5784f875fdc2e3436ed15c444ddca63e3d7` supplies the package version and tarball integrity. Select the first 12 eligible unique top-level unscoped package names by SHA-256 of `asi-dist-v1:{name}`. Require a standard public npm tarball URL, an exact semver and sha512 integrity. Include every selected lineage in results even if verification fails. An npm tarball authenticated against its pinned integrity is the reference for expected file bytes. Read only the archive member `package/package.json` without extracting or executing a package. [Lockfile source](https://github.com/npm/cli/blob/977fd5784f875fdc2e3436ed15c444ddca63e3d7/package-lock.json) · [Lockfile semantics](https://docs.npmjs.com/cli/v10/configuring-npm/package-lock-json/)

Use version-pinned direct reads from jsDelivr and UNPKG. The services operate independent observation paths to the consuming client. Both depend on the same npm release, and transport components and the client may share infrastructure. This protocol supplies no claim about independent publication origins or correlated outage frequency. Alternate which service is read first. Record HTTP status, redirects, exact bytes received, SHA-256, timing, and error class. Do not reroll failures. Read at most 16 MiB per tarball and 128 KiB per manifest. [jsDelivr](https://www.jsdelivr.com/documentation) · [UNPKG](https://unpkg.com/)

Report observed first-path latency and bytes and the ledger for three replay arms:

- Primary only attempts the jsDelivr read and closes only on a match to the known expected file.
- Caller fallback and gateway fallback share the same checked observation and one second-read budget. Withhold closure if the reference cannot be verified, if both paths fail, or if the only returned evidence is a mismatched file. Count one extra caller request for caller fallback. Charge gateway fallback for the second service request and the compact JSON status envelope, including the original artifact identity and digest. Protocol body-byte counts exclude headers, redirects, TLS, retransmission and runtime service overhead. The timing comparison sums the actual captured fetch durations for the reads each arm would use. It supplies no gateway execution latency or placement throughput.
- Score four prespecified availability strata on every lineage. The observed stratum uses the live observations unchanged. The other strata mask the primary, mask both, or remove the primary and supply the next sampled lineage's second-path file as an adverse wrong-body control. These masks and substitutions are offline perturbations of real observations. They do not estimate natural interruption or error rates. Unsupported closure counts as false even when the case's known version exists. Count each unresolved or held outcome.

A follow-up can proceed to a broader comparison if adding the second read resolves at least 3 of 12 primary-unavailable lineages with zero false closures in the joint-unavailability and wrong-body controls. Report extra response-body bytes per recovered closure against a provisional 8 KiB threshold and the added-read median against 1 second. This is a screening rule and not an error-rate or deployment-acceptance bound. Production adoption remains conditional on a new population of actual interruptions and on human work measurement. The script records measured automated processing time and manual-review opportunities. Measure staff time by timing active diagnosis, selection and record entry for each held submission, pausing for service wait and unrelated work. Report separately with the number of reviewers and timed sessions. Leave staff time null when no human session occurs.
