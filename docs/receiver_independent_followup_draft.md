# Draft protocol for an independently operated receiver study

This protocol is for author review. It records a proposed experiment. The study registry continues to count received reports separately.

## Decision and provenance

The prospective local receiver run compared primary-only status, gateway-mediated second status and a caller-issued second lookup. Under matched second-source access, both second-source arms closed 80 of 288 caller requests, compared with 48 for primary-only status. Gateway placement saved 192 caller requests and spent 54,168 additional status payload bytes. In pair 024, the fresh second projection let both placements verify an existing effect. In pair 064, both projections were unavailable and all three arms held despite a prior effect. These are authored cases using same-owner services. The replay kit and pinned result establish that comparison on its original conditions. [Receiver study](https://corbensorenson.github.io/asi-stack-book/products/evidence-registry/study-crossed-receiver.html#run-receiver-availability)

Ask whether a second status path that is independently operated and connected to a genuinely separate observation resolves more outcomes safely under the same access, retry and latency budget. Separately ask whether placement changes resolution when paths have matching access. Register these two decisions separately before inspecting outcomes.

## Comparison

- A conventional caller uses the primary receipt, its normal independently available status sources, and competent retry and deduplication rules. Freeze exactly what its real operational access includes.
- A gateway and a caller each receive matching permission, time, freshness and retry budgets for the second route. Use the same effect-checking rule, with separately recorded fault and policy configuration. Compare these two arms for placement.
- Cross each feasible workflow with a shared upstream dependency and a separately operated second path. A second database carrying the same delayed observation belongs in the shared stratum. Record upstream origin, administrative control, deployment and observability dependencies. Change placement without changing source access. Change source independence without changing placement. Keep any infeasible combinations visible.
- Cross unavailability, successful stale replies, wrong effect identity, duplicate effects, and release of a retry after an ambiguous commit. Include receiver deduplication and non-deduplication in isolated fixtures. Use an outside or separately controlled truth log keyed by effect identity to score every route, including unverifiable and late outcomes. Treat a wrong or repeated effect as its own outcome.

## Freeze and measure

Ask an independent operator to write new task lineages and a fault schedule. Predeclare the task population, eligible effect identities, expected availability strata, acceptable error and latency margins, permissions and maximum retry budget. Freeze randomization, sample-size justification, code revisions and the result schema before replay. Derive the unit of uncertainty from independent task or incident lineages. Record all arms on the same eligible requests where isolation permits, and report both conditional strata and full intention-to-treat denominators. A repeated case or retry contributes work and observations within its lineage.

Record verified closures, false closures, otherwise correct holds, missing outcomes, wrong and repeated effects, time to correct resolution, attempts, calls, payload bytes, and separately measured active operator time and service cost. Use a declared operator-time clock and staffing protocol or mark labor unmeasured. Report paired differences with uncertainty and expose stratum counts alongside the combined estimate. Declare an acceptable safety margin with the reviewer and gate the cost comparison on that margin. If a path passes only in a narrow fault cell, report that restriction.

Archive the independent protocol, exclusions, failures and exact versions through the existing independent-check form. Repeat the original replay as an environment control and label it separately from changed assumptions and any independent result.
